# 任务进度看板 Implementation Plan

> **For Hermes:** Follow the approved brief, implement vertical slices with failing tests first, then run a separate spec/security review. Only feat/kanban-20261115 may be pushed; do not merge.

**Goal:** 基于 origin/experiment/minus-one-widget @ 40fb8d31114b18fe6aed2d9f43c112e5b70146f7，提供负一屏安全尺寸的 8 槽任务看板、零 LLM 聚合脚本、真实 CI APK。

**Architecture:** 聚合器只读 keeper 与显式进度源，在手机 Documents 暂存契约 JSON。手动 `--push` 使用已有 MCP `fs_write/fs_read` 将数据写入 `widgets/task-kanban/看板.json`；DataRepo 每次渲染读取该文件并合并 `parcel.N.*` 槽位。模板为 APK 内置的 JSON asset，单一真源；4x4/2x4 显示 8 项、4x2 显示 4 项、2x2 显示 2 项，缩略版明确标注未展示项。

**Tech Stack:** Kotlin/Android Canvas、org.json、Python 标准库；仅测试使用 JUnit/Robolectric，运行时不增加第三方依赖。

## 已批准的边界和测试接口

依据用户本棒简报“开干”和交付定义执行，不重做产品决策。公开接口验收：看板 JSON 契约、脚本 CLI、MCP 文件写/回读/data_snapshot/data_refresh、SpecValidator、Renderer Bitmap。任何百分比只能来自显式字段或进度文档明确百分比；未知用 progress=0 加 note 标记，组件显示“—”而不是假 0%。

现况核实：实验基线 versionCode=26/versionName=0.3.8-exp5；本棒 code=27/name=0.3.9-kanban。仓库 GitHub API private=false，因此禁止提交真实看板数据、其他任务线信息、运行时映射、凭据。工作区隔离，不动 master。
